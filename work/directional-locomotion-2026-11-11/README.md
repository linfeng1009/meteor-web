# 蹲走与方向跳跃动作修复

用户报告蹲姿移动只有平移、侧跳和后跳与原版动作不同。原实现将所有蹲姿强制设为10，所有跳跃统一151/152，确实漏接了原资源已有的方向动作。

## 原版证据

- `work/meteor-original/evidence/jump-physics-detail-2026-11-05/004cc730_FUN_004cc730.c`：下蹲标志为真时，将站立映射为10，140/144→145、141→146、142→147、143→148，分别为前、右、左、后蹲走。
- `work/meteor-original/evidence/jump-entry-native-2026-11-05/004cf770_FUN_004cf770.c`：前后输入优先于横向输入；起跳选择151/153/155/157。
- `work/meteor-original/evidence/hit-reaction-getup-2026-10-30/004cf7d0_FUN_004cf7d0.c`：空中对应152/154/156/158，侧跳和后跳不应退回通用前跳。
- 实际P0 POS含上述全部帧区间、循环和链接，153→154、155→156、157→158；AMB包含各自不同的骨骼动作及d_base高度轨迹。动作名称另可参考[动作资料表](https://www.lxres.com/LiuXingBiJi/1758.html)，实现依据为本地原资源与原控制函数。

## 改动

蹲姿移动根据方向播放145–148原循环，保留面向镜头的朝向以呈现侧步/后退，而非一律转身套用前进动作；松开方向后，减速阶段继续当前循环，停下回到10，松开蹲键回武器待机。

跳跃由实际控制该角色的按键选择方向：前/原地151→152，右153→154，左155→156，后157→158（后空翻）。起跳高度轨迹也采样所选动作，不再所有方向套用151的d_base；保持本次起跳的朝向与空中动作族，空中换方向不会重启新的起跳。碰撞落地或重生后清理该序列。联机房主处理客人时读取客人的control，不读取本地玩家的按键；客人继续通过现有pose/source/frame同步显示，无协议修改。

原地前跳、受击、空中攻击、蹲姿双击翻滚和站姿闪避仍沿现有规则处理。未在本轮添加蹬墙跳、二段跳、落地取消，未改动现有Web移动速度/重力常数；不宣称完整移动系统或所有原版速度已经还原。
