# 鼠标视角与帧率优化

## 实施计划及完成内容

1. 增加基于 requestAnimationFrame 时间戳的帧率、平均帧耗时、P95 帧耗时和 CPU 分段测量。固定大小环形采样，界面每0.5秒更新一次；设置里可以关闭显示，偏好保存在本机。切回页面、重新开始或恢复游戏时重置采样，避免载入及后台时间污染。
2. 检查视角路径：原先鼠标角度更新后，相机位置仍以 `1-exp(-dt*10)` 追赶，时间常数约100ms。鼠标锁定及拖动时改为当帧应用轨道角度，保留目标位置跟随和三角形墙体遮挡；自由视角减少一次重复碰撞射线。锁定目标和菜单镜头保留平滑。
3. 静态地图碰撞使用16米网格筛选候选物，超大物体保守保留；动态机关继续走现有实时查询。最终命中仍由原三角形射线决定，不改变伤害、移动、世界固定步长或联机协议。
4. 持续低于52 FPS、CPU未超预算时逐步减少渲染倍率，稳定后缓慢恢复，分别以高/低画质原有倍率为上限，最低不低于0.75（设备原倍率更低时保持原倍率）。后台、暂停、菜单、明显长停顿及CPU繁忙时不触发调整。目标为60 FPS预算，不能保证所有硬件/模型/地图固定达到60 FPS。
5. 增加原地图碰撞基准及浏览器诊断页，完成自动回归后提交推送，补入现有PR待审核。

## 已验证证据

`node scripts/benchmark-collision.mjs` 读取实际GMB与DES，两张地图各600条地面/视角射线，全场查询与索引查询逐条命中距离和数量一致。预热后交替运行7轮、每轮1800条射线，中位数见 [collision-benchmark.json](collision-benchmark.json)：

| 地图 | 全场查询 | 索引查询 | 附近候选物均值 / 原数量 |
| --- | ---: | ---: | ---: |
| 四方阵 | 4.247 ms | 1.288 ms | 3.04 / 81 |
| 炎硫岛 | 4.109 ms | 3.137 ms | 3.16 / 33 |

这是CPU碰撞微基准（约70% / 24%提速），不是端到端FPS提升比例，也不测GPU。较早未应用DES碰撞标记的初测为21% / 12%，以上实际DES复核结果为准。

单元测试覆盖30/60/144Hz帧率统计、P95、暂停恢复、倍率调整迟滞及上下限、动态场景物件、真实墙体遮挡、鼠标轨道当帧响应，结合原有跳跃/闪避/固定步长回归。

## 浏览器验收状态与复核方法

诊断页 `/performance-lab.html` 固定原版人物、原版长剑、高画质和三名对手，预热5秒再采集10秒，默认关闭自动倍率以便比较。通过与鼠标相同的角度函数匀速转向；这不是物理鼠标设备延迟测量。保持窗口前台，长停顿或隐藏状态会标记结果不适合比较。

本轮浏览器采样曾出现约1秒一帧、帧内CPU约33ms的异常限速；页面报告visible，原因尚未确认，不能认定正常前台游戏只有1 FPS。随后原生浏览器控制因无法确认窗口网址被工具停止，未能完成可信的前台优化前后FPS对比或真实鼠标实战验收。因此不宣称已实测达到稳定60 FPS。

当前4173服务直接读取dist，刷新页面即可加载前端改动，无需重启联机中继。请在常用高清人物与地图下，比较原地/鼠标持续转向/移动攻击时的FPS及P95；需要时用流畅优先档观察渲染倍率。GPU驱动、显示器刷新率和高面数模组仍会影响结果。

最终回归：526/526 项测试通过，48 个运行模块语法检查通过。
