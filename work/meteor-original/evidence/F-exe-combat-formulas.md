# 原版 Meteor.exe 战斗数值证据

样本 SHA-256：`289afb0aa44a47921d167fc24d6d404c60d6d00c299ac27d45fc61e16231b498`。本次只静态分析，没有执行客户端。

原生角色 `+0x88` 的属性虚表为 `0x5a9490`；属性 1/2 是最大/当前 HP，3/4 是攻击/防御，6/7 是当前/最大怒气。

## 可接入的精确计算

1. `004d61c0`：先取有效攻击 A。姿态 RES 中的 mode=1 系数 c 产生增量 `trunc((c * float32(0.01) - 1) * A)`，加到 A。mode=0 直接相加。
2. `004d6190`：姿态攻击减目标有效防御。
3. `004d5f70`：`D=trunc((姿态攻击-防御)*factor)`；D>0 才扣目标 raw HP。`004af630` 给正常阵营 factor=1，同队 mask 相交 factor=0.2。
4. 受击者怒气增加 `floor(14*(实际HP损失)/100)`。防御分支增加 `trunc(14*(姿态攻击-防御)/500)`，敌方且结果>0 才加；当前分支条件为包中特定位为0且目标 `+0x20c==1`。
5. HP 和怒气调整由 `004d4d30` 限制在 0..各自最大值，初始最大怒气100。

`004d61c0` 的 x87 基数尤其容易被反编译输出误导：`004d6284` 把有效攻击保存在 `[esp+0x14]`，`004d62ac` 的 `push ebp` 使栈移4字节，因此 `004d62f1 fimul [esp+0x18]` 仍指向有效攻击，不是 getStat 的 base-out 参数。

## HP 单位

`004bf650` 在查 PlayerHP 前写默认1000，只有字段存在才覆盖。`004d4a70` 用 `trunc(floatRatio*1000)` 同时初始化当前/最大HP；调用点 `004ac453` 先把整型配置乘0.01。`server.cfg life_adjust` 是百分比配置的读取语义已找到（`0045b0a0` 保存到对象+0x70），到游戏对象+0x23c的完整字段传播还需补齐，但基础默认1000已无歧义。

## 附加效果不是出招消耗

`004af630` 命中后以**受击者**属性接口+0x48调用 `004d5fc0(3,pose)`，解析姿态 parameter16 引用的 type2道具，再按受击者 ID 应用。因此 item21(-10怒气)、item22(-20)、item37(-5) 是命中附加效果，不能当作攻击者消费。
