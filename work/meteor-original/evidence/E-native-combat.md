## Static findings

`parsePos()` consumes all 574 P0.POS records; 479 contain valid frame intervals. `parseAct()` yields 160 groups and 191 outgoing-connection records. Repeated blocks, quoted multi-line bone lists, comments, case variation, leading-zero numbers and overlapping phase intervals are retained.

All nine basic poses explicitly name their weapon in the original Traditional Chinese comment. The connections above exist in character.act (they are not inferred from consecutive IDs). Source 0 references Common/character.amb; source 1 references the character-specific p0.amb. Both BANIM headers contain frame rate 30, independently parsed by the character-resource subtask.

The runtime exports the original bone selections, TargetValue, TargetMove, DefenseValue, DefenseMove, TargetPose and directional hit reactions as raw values. No assertion is made here that a raw field equals HP damage; its arithmetic needs executable analysis.

## Runtime behavior and confidence

- `NativePoseTimeline` addresses original source/frame numbers, advances at 30 FPS with POS per-phase Speed and reports interval crossings so a low render rate cannot miss a narrow attack window.
- `NativeCombatController` only permits attack-to-attack links that exist in character.act and reads cancellation windows from original NextPose blocks. The exact executable handling of NextPose.Time and overlapping speed precedence has not yet been independently confirmed; the browser implementation uses later matching phase precedence and immediate cancellation inside the declared interval.
- Original bone/root sampling is delegated to native-character.js. No procedural fighting animation is generated by this module.
- Directional input-to-pose mapping is **not** present in these two files. The implemented directional commands are cross-checked against the community action table recorded in `dist/assets/original/characters/pose-reference.json`; every target must exist locally and any attack continuation must obey character.act. This is external corroboration rather than an executable-disassembly claim. The input sequence buffer duration is a browser-host parameter; its original executable value is not yet established.
- Stance/locomotion IDs (sword 6/16, spear 7/17, blade 8/18; walk 140, run 144, jump 151→152, hit 90, death 117) are cross-checked against the community action table at https://www.lxres.com/LiuXingBiJi/1758.html. They are external corroboration, not proof of executable control flow.

## Native browser-host integration delta

The previous procedural prototype engine is preserved at `work/meteor-original/archive/prototype-engine.js`. The active `dist/engine.js` now renders extracted local GMB maps and SKC/BNC/AMB characters at a uniform native scale 0.08, uses extracted original GMC weapons on animated d_wpnR attachments, and applies original attack root-X/Y deltas. It does not construct replacement bodies or scenery.

Spawns use original DES D_user records for the multiplayer rehearsal scene, independently of Level PlayerSpawn waypoint indices. Original map geometry is used for ground, wall, and camera ray tests. Hidden DES collision platforms must remain collidable even when visible=0; treating them as absent was identified as the cause of sn10 high-altitude spawn failure and handed to the loader owner for correction. COB binary collision semantics remain unported; triangle-ray collision is an explicitly provisional browser host.

The UI time is elapsed rehearsal time. No invented five-kill or three-minute original rule is applied. A verified resolver is now installed by default using the recovered EXE stat/pose/defense arithmetic (E-exe-combat-formulas.json). Contact events retain the original POS fields and complete Meteor.res move/weapon records. Source level PlayerHP is used when present; otherwise the recovered original default is raw HP 1000 (004bf650).

Native sound playback follows extracted EF soundReferences into original WAV files. The host currently triggers the selected EF sound at animation start/contact; the binary EF's internal event delays have not yet been decoded and are not claimed as accurate timing.

The original first-mission PST VM now runs through native-mission-host.js. Core pending items remain explicit in onUpdate.native: original physical constants, machine collision volumes and advanced/native projectile semantics. Browser contact radii, AI movement timing/perception and the Rule-10 completion fallback remain identified adapters. This is not a claim that the Windows executable has been fully decompiled or ported.
