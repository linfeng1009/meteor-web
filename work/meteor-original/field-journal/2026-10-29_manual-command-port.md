# 旧游戏手动连招移植的覆盖审计

日期：2026-10-29。范围：已授权本地样本的静态资源分析、Web实现与本机验证。此记录仅写入项目内；未写外部技能目录或记忆。原样本未执行或修改。设备路径、用户名和部署标识均省略，原文件位置以 `{sample_dir}` 表示。

## 从输入覆盖率检查缺口

资源存在、动作可播放、手动输入可达、命中有效和完整效果，是不同层次。建立“兵器＋手动入口”目录，同时记录地面 / 空中、前置动作、怒气门槛、原姿态及未完成项。以旧运行时实际可选目标比较新增入口，不把从未被选择器使用的special数组算作已实现，也不把自动后续算成必须再手搓一次的新招。

社区方向表与姿态表可能互相矛盾。同一输入被重复标到两个不同动作时，需核对免费 / 耗怒、反向输入、破防类型与原注释，记录采用哪一份资料以及其不确定性。ACT的可达边只证明动作可以连接，不证明该边的输入指令。原EXE输入识别器尚未恢复时，社区映射和Web容错参数必须独立标识。

## 保住整条动作链

不能用“当前姿态有无攻击窗”决定是否正在攻击。起手、飞空恢复或自动Link中的某一阶段可以没有攻击块，却仍占用整条招式。保留原输入动作身份、自动阶段与整链busy，避免待机 / 跳跃姿态抢占起手。

队列应在原取消窗开始时执行；大dt跨过整个窗口时仍要处理。资源费用在真正起手时重新检查并扣除，提前输入只排队，自动后续不重复扣费。死亡、切换兵器和失败起手都应清掉队列。落地保持帧重复取样不能重复命中。

一次update可跨越多个姿态或多个攻击窗。返回各原片段而非仅最终姿态，按片段原帧取样真实骨骼 / 武器挂点，再用serial＋窗口＋目标去重。用高低两种帧率检查同一多段招式的命中数和累计伤害一致；只检查最终pose ID会漏掉这类问题。

攻击文件中的身体骨骼名与骨架文件的名字可能只有空格 / 下划线差异，肉眼看起来相同却查不到节点。先比原数据，做范围明确的标准化，并让角色与机关命中都走同一解析入口；回归必须实际验证踢击 / 腿击伤害，不能只测姿态选择。effect名字解析失败不能套同一规则猜成身体节点。

破防类型必须追完整字段链：语法归约 / 记录偏移→命中封包→受击分支，再接Web有效护架。仅看到AttackType=1或“破防”招式名不足以恢复防御规则。此次原分支支持非0类型绕过护架伤害，但不证明护架角度、硬直或击退已恢复；声音和事件也要使用同一有效护架结果。

## “有攻击块”仍可能空挥

末轮独立复核发现一条耗怒招式只有effect攻击引用，没有已接通的实际命中体。目录、帧和RES全部存在也不能让它被算作可用。该招明确pending，输入被拒绝且不扣怒；不能退化普通攻击掩盖缺口。另一招首窗含weapon、后窗只有effect，应保留可用首击，同时明确后半效果未完成。

投射也应分层：发射、飞行碰撞和直接伤害通过，不等于RES附带item的持续状态传播完成。复杂EF文件有父绑定、通道和多个形状体，“八方”名字不是发射数量或角度证据。保持原字节、类型表和节点inventory，不造扇形弹替代原攻击体。
