# NPC 原始蹲守分支

## 原程序证据

参考客户端 005043d1..00504422：进入 Guard 权重后另取 rand()%5。余数为 0 时调用 00501280(1)，否则调用 00500c40(1)，两者都将下一次决策基础间隔设为 float32(.4)。非防御决策先对这两个入口传 0。

00501280 调用角色虚表 +ac，落到 004ce1c0，写角色 +80 的蹲下标志。004cf8b0 对该标志选择原 Pose10；它不是伤害防御标志。00500c40 经角色虚表 +a8 控制格挡。两个置位分支都不清除另一标志，因此不能简单把站立格挡随机替换成互斥的另一种状态。

十二种武器虚表的 +40 均为 004e4080，返回 0；004ce1c0 的拒绝检查因此不会额外拒绝某一种武器。浏览器实际姿态仍由现有受击、攻击、瞄准和地面状态规则决定。

旧工作区原样本相应调用地址为 00504407/0050441d/00504438/00504442，入口为 005012a0。不能跨样本不加区分地复用偏移。

## 变化

- 恢复独立的五选一随机抽样及蹲下标志；非防御、失去目标、离开攻击决策范围和重置清理两种标志。
- 主机的原蹲姿/蹲行动画读取该标志。已有格挡和受击仍优先。
- NPC 蹲行使用原动画步幅校准速度，保留剧情速度倍率，避免把站立追赶速度用于蹲行。步幅校准仍是 Web 适配，不是从 EXE 恢复的速度常数。
- 决策事件附带实际防御分支，便于检查。

## 回归范围

新增五选一分支、原标志保留/清理、暂停、真实人物蹲姿与行走距离、格挡/受击优先及主机决策到姿态的集成验证。

原站立防御测试的固定随机数 0 现在正确选中蹲守；改用余数为 1 的固定抽样继续检查原站立格挡伤害路径，另加随机数 0 的真实蹲守集成测试。

剧情 seed4 的旧测试玩家在敌人因新防御抽样改变位置后，持续朝墙后的最近目标直走，双方视线已被原地图阻挡。测试玩家现在优先接近可见敌人，视线受阻时沿已有原 WP 路径行走；仍只发送正常移动输入，不改 HP、死亡、敌人脚本意图或伤害规则，也没有延长原时限。四组固定种子的实际攻击致死和重开检查继续执行。

专项及集成 74 项通过；补充真实蹲守集成后，最终全量 737 项、719 通过，18 项仍为既有角色源资源缺失，无新增失败。61 个运行模块语法检查及差异空白检查通过，回环与局域网 HTTP 均为 200。仅改前端主机逻辑，未操作原版窗口，也不重启局域网服务。

## 移动惯性核查更正

004e34e0 在忍刀攻击请求成功时对角色 +3b8/+3bc 乘 float32(.67)。004ce840 将该通道独立于动画 d_base 位移衰减，系数来自 005a9b30(.2) 与 005aa928(9)。但 004cbf00 复制 +390/+394/+398 到该通道的调用实际进入状态6及闪身/翻滚姿态，不能把它当作所有普通跳跃的初始化证据。真正的起跳、离地及普通空中移动入口尚需继续追踪；本次没有按这个未经证实的推断改动跳跃。
