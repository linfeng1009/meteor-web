# 自动拾取与双兵器闭环

## 完成范围

演武、原版单机和房主模拟的玩家在地面靠近已支持物品时自动拾取。F仅作为辅助入口，不再是必需操作。原地图的武器模型通过原weapon-models清单映射到具体RES武器记录，收为副兵器；两槽已满时不替换、不销毁地面武器。E只交换主副兵器，G丢弃副兵器，触屏增加“丢”。演武数字键选兵器仍保留为演练扩展。

丢弃生成原缓存模型的可拾取实例；持有者须离开接触范围才能重新拾取，别人可以立即拾取。死亡掉落当前手持兵器；重生和剧情初始化从原配置恢复副兵器或空槽。读取失败、切换期间重复输入或旧局异步完成不能凭空消耗库存；掉落实例有64个上限，成功拾取释放实例，新局/菜单/离开联机/销毁清理。

道具数值复用已验证的原RES消费者：回血、怒气、防御/攻击/移速/气血上限及毒肉包持续作用。满血/满怒时保留相应即时回复物品，附近有可用物品时优先选可用物品；可达性、原active/interactive及脚本输入禁用继续生效。未恢复消费者的物品不会被错误吞掉。

## 表现与还原边界

成功拾取道具和武器均调用现有原`getitem.ef`可渲染节点及Get.wav。此次没有修改原特效关键帧、纹理或数值。已有EF播放器对PARTICLE节点等仍有未恢复部分，不宣称原版全部粒子/持续附身特效已经齐全。

可拾取静态模型增加旋转和轻微浮动，变换只作用于视觉子模型，拾取坐标不随浮动偏移；有原FMC的模型保留其原动画。这是网页展示适配，不冒称已经恢复原EXE的旋转/浮动常量。未虚构弯腰拾取姿势或换武器24动作；原版精确拾取门限、满资源策略和丢弃轨迹仍待源码证据确认。本轮使用既有1.8米水平/2米高差、地面非攻击/非格挡自动拾取，库存满/空和防止本人立即吸回也明确属于适配规则。

## 联机

协议升级为3：客人只提交switch/drop/pickup操作，沿既有序号重试/确认链送给房主；HP、物品消失、库存和掉落均由房主决定。快照增加主副兵器、拾取序号、场景已消费物品名及有界掉落列表；服务验证形状、数量和数值。客人不执行拾取或数值效果，只更新模型/状态、隐藏消费物品并播放一次拾取反馈。掉落模型加载途中已被拿走时不能在加载完成后复活。旧协议页面明确拒绝，需要刷新双方页面；开发服务已重启保持4173本机及局域网监听。

客人的增益状态名称、数值及剩余时间也由房主快照驱动，退出联机清除副本状态，避免回到单机残留。live-api-check.mjs针对实际4173服务建立两个独立身份，验证三种库存操作重试不重复排队、房主确认后清空、掉落与消费快照传递、客人不能发布世界状态，以及非法坐标拒绝；结果见live-api-result.json。临时房间在finally中关闭，不记录身份凭据。

## 验证与结果

新增11项回归覆盖同一物品争抢只消费一次、双槽容量、本人丢弃锁、演武/剧情自动拾取与门禁、视觉独立/重置、库存读取失败/旧局取消、实际原缓存模型掉落、旧自定义键位迁移不抢占G、服务端操作重试/快照校验、异步掉落取消、客人库存和反馈去重。既有按E轮换12种武器的测试改为菜单能装备12类、E不得生成不存在的副武器；剧情初始0空槽继续严格回归。

浏览器临时入口使用真实四方阵DES道具/武器及原人物：隔离NPC，将人物摆在原物品附近有地面的起点，再通过前进输入与固定步长完成接近，未直接赋值拾取结果、血量或库存。验证碧血→收取怒火→切到怒火/副碧血→丢碧血→离开走回收取碧血，以及铜皮防御+20/90秒与拾取光效。截图见inventory-proof.png和buff-proof.png。为留住短暂光效，暂停后冻结验收入口的表现时间；浏览器存在后台1FPS节流，这些截图不作为帧率或真实双人手动实战结论。browser-check.html为临时入口源文件，验收后删除dist副本。

全量回归579项：569通过，10项仍为既有空/芙宁娜/荧/王昭君本地源归档缺失，没有新增失败。51个运行模块语法检查和差异空白检查通过。主分支不自动合并。
