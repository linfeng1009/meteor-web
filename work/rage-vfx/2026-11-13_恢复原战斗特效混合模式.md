# 恢复原战斗特效混合模式

本阶段只读原程序、原资源并做后台测试，没有操作桌面或运行原客户端。

## 原程序依据

0058e8a0 读取纹理名后材质块偏移 81/85/89 三个 uint32，写入材质 +90/+94/+98。0058e540 根据 +90 选择模式：0 禁用混合；1 使用源颜色与 1；2 使用 0 与反向源颜色；3 使用源透明度与反向源透明度；4 由另外两个字段选择自定义因子。固定模式不使用后两个字段。

0058e6d0 将文件因子索引 0～9 映射为引擎枚举 `[1,0,2,4,6,7,3,5,8,9]`；00475840 的字符串表确认它们分别为 1、0、s、1-s、sa、1-sa、d、1-d、da、1-da。00475980 依照模式启用混合并设置这两个因子。机器码范围、哈希和字段布局保存在 effect-blend-evidence.json，已从同一参考 PE 独立核验。

## 实现

保留每个节点原始 blend 三字，并在创建材质时映射到对应混合状态。除模式 0 外使用 CustomBlending 与加法方程，颜色和 alpha 均采用原来的同一对因子，不借 Three 的 NormalBlending 快捷方式改变 alpha 结果。

先前所有显示一律加亮，颜色叠加、减暗和普通透明粒子因此被混同。现在飞轮夺命轮盘的 BlackBall 等暗色节点使用 `destination*(1-sourceColor)`，匕首空中 Board_1 等斩痕使用 `source*sourceColor+destination`，火铳烟雾粒子使用普通源 alpha 混合；原加亮节点仍使用源 alpha 与 1。

颜色叠加和减暗不依赖源 alpha，因此不能再仅因为关键帧 alpha 为 0 就删除它们的显示。只有源 alpha/1 或源 alpha/反向源 alpha 这两种公式才沿用透明度零时略过显示的规则。原隐藏标记、关键帧颜色、贴图及其他显示规则保留。

原内容去重后 2412 个材质记录包含模式 0/1/2/3/4 各 1101/15/9/499/788 个。现有可见网格中有 9 个颜色叠加、9 个减暗节点；普通透明模式还用于粒子。对三份清单去除新增 blend 后，均与提交前 JSON 完全相同，未重建特效定义或粒子启用策略。

新命令 `python -S scripts/import-effect-blend.py --check` 可用标准库复核所有原字段；未知模式及自定义因子会被拒绝，固定模式的未使用因子字原样保留。混合状态只在材质创建时配置，不新增贴图、网格或绘制调用。
